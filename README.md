# Lumen

Контроллер адресной ленты на ESP32 с декларативным планировщиком.
Говорит на JSON API, совместимом с WLED, — за счёт этого Home Assistant
находит устройство сам, без custom_component и без YAML.

Собирается под две платы: **ESP32-C3 Super Mini** и **ESP32 DevKit (WROOM-32)**.

Статус: этапы **M0** (каркас, провижининг, OTA) и **M1** (лента, эффекты,
JSON API, mDNS) готовы. Ядро планировщика написано и покрыто тестами;
применение пресетов целиком — этап M4, веб-интерфейс — M3.

---

## Быстрый старт

```bash
pio run -e devkit_wroom32 -t upload      # прошить DevKit
pio run -e supermini_c3 -t upload        # прошить C3 Super Mini
pio device monitor                       # смотреть лог

pio test -e native                       # тесты ядра планировщика
```

Тесты ядра можно гонять и без PlatformIO:

```bash
g++ -std=c++17 -I lib/schedule lib/schedule/*.cpp \
    test/test_schedule/test_main.cpp -o /tmp/lumen_test && /tmp/lumen_test
```

При первом включении устройство поднимает точку доступа `Lumen-XXXX`.
Подключаетесь к ней, открывается портал, вводите имя сети и пароль.
После перезапуска контроллер доступен как `http://lumen.local`.

## Схема подключения

```
   5 V PSU ──┬────────────────────────── +5 V ленты
             │
             ├── 1000 мкФ (по питанию, у первого диода)
             │
             └── GND ──┬──────────────── GND ленты
                       │
                     GND ESP32

   ESP32 GPIO ── 74AHCT125 ── 330 Ом ── DIN ленты
       (3.3 V)     (сдвиг      (гасит
                   до 5 V)     отражения)
```

Пины по умолчанию: **GPIO2** на C3 Super Mini, **GPIO16** на WROOM-32
(меняются в `platformio.ini`).

Три вещи, на которых ловятся почти все:

- **Level shifter обязателен.** WS2812 ждёт логическую единицу от 0.7×VDD =
  3.5 В, а ESP32 даёт 3.3 В. Часто «работает и так» — до первого нагрева
  или замены катушки ленты.
- **Общая земля** между блоком питания и ESP32. Без неё сигнал плавает.
- **Инжекция питания** каждые ~150 диодов, иначе дальний конец уходит в
  красноту: медь дорожек не бесконечная.

## Home Assistant

Ничего настраивать не нужно. Устройство анонсирует mDNS-сервис
`_wled._tcp.local.` — именно его слушает встроенная интеграция WLED.
Через минуту после включения HA покажет его в *Настройки → Устройства и
службы* как обнаруженное.

Что важно знать про эту интеграцию:

- Она требует версию прошивки 0.14.0 или новее, поэтому `/json/info`
  отдаёт `"ver": "0.15.0"`. Собственный номер Lumen лежит рядом, в поле
  `"lumen"`.
- Имена сегментов игнорируются: в HA они всегда «Segment 1», «Segment 2».
- Мастер-контроля над всеми сегментами разом у интеграции нет.

Расписание при этом исполняется **на устройстве**. Если сервер с Home
Assistant выключится, лента продолжит жить по графику.

## Планировщик

Правило описывает **интервал**, а не момент времени. Это главное отличие
от событийной модели: резолвер отвечает на вопрос «какое правило действует
прямо сейчас», а не «какое событие только что произошло».

Практическая разница: контроллер перезагрузился в 19:00, внутри окна
18:00–23:00. Событийная модель уже пропустила своё «включить в 18:00» и
оставит ленту тёмной. Резолвер посчитает состояние заново и сразу
восстановит нужную яркость — вместе с позицией внутри fade-огибающей.

```jsonc
{
  "id": 1,
  "enabled": true,
  "priority": 0,
  "from": { "type": "sunset", "value": -30 },   // за 30 мин до заката
  "to":   { "type": "clock",  "value": 1410 },  // 23:30 в минутах
  "days": 127,                                  // битовая маска, бит 0 = вс
  "except": ["2026-12-25"],                     // календарные исключения
  "action": { "preset": -1, "bri": 180, "powerOff": false },
  "fadeIn": 1800,
  "fadeOut": 900
}
```

Что умеет ядро:

- якоря на часах, восходе и закате со смещением в обе стороны;
- окна через полночь (22:00 → 06:00) — дни недели проверяются по дню
  **начала** окна;
- приоритеты: правило «вечеринка» перебивает фоновое, не отменяя его;
- ужимание фейдов, если они не помещаются в окно;
- отказ срабатывать, пока время не синхронизировано с NTP.

Восход и закат считаются на устройстве по алгоритму NOAA из координат —
сети для этого не нужно. Для Варшавы расхождение с реальностью в пределах
минуты (21 июня: 04:14 / 21:01, 21 декабря: 07:43 / 15:25).

Перенос на летнее время берёт на себя POSIX TZ-строка
(`CET-1CEST,M3.5.0,M10.5.0/3` для Польши) — таблицы правил в прошивке нет.

Залить пример:

```bash
curl -X POST http://lumen.local/api/schedule \
     -H 'Content-Type: application/json' \
     -d @examples/schedule.example.json
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/json` | состояние, info, список эффектов и палитр |
| GET | `/json/state` | только состояние |
| GET | `/json/info` | версия, железо, uptime, free heap |
| POST | `/json/state` | управление (совместимо с WLED) |
| GET | `/api/schedule` | текущее расписание |
| POST | `/api/schedule` | заменить расписание целиком |
| WS | `/ws` | состояние в реальном времени |

```bash
curl -X POST http://lumen.local/json/state \
     -H 'Content-Type: application/json' \
     -d '{"on":true,"bri":200,"seg":[{"id":0,"fx":4,"sx":180,"pal":2}]}'
```

## Структура

```
lib/schedule/         ядро планировщика — без Arduino, тестируется на хосте
  solar.{h,cpp}         восход/закат, календарь
  schedule.{h,cpp}      резолвер интервалов и огибающих
test/test_schedule/   48 тестов ядра, включая прогон целого года
src/
  core/state.*          состояние под мьютексом
  core/scheduler_runner.*  мост: NTP, TZ, координаты → ядро → лента
  led/effects.*         движок эффектов и палитры
  led/led_controller.*  NeoPixelBus, сегменты, гамма
  net/wifi_provision.*  подключение и captive-портал
  net/discovery.*       mDNS `_wled._tcp`
  net/web_server.*      HTTP + WebSocket
  net/ota.*             обновление по воздуху
  store/store.*         config.json и schedule.json на LittleFS
```

Ядро планировщика намеренно не знает ни про Arduino, ни про `time()`:
на вход ему подаются дата, минута суток и солнечные времена. Поэтому год
виртуального времени прогоняется тестом за долю секунды, а краевые случаи
(переход на летнее время, окна через полночь, полярная ночь) ловятся на
хосте, а не на столе с осциллографом.

## Различия между платами

| | C3 Super Mini | DevKit WROOM-32 |
|---|---|---|
| Ядра | 1 (RISC-V) | 2 |
| Рендер | в основном цикле | отдельная задача на ядре 0 |
| Диодов по умолчанию | 300 | 1200 |
| Сегментов | 4 | 16 |
| Serial | USB-CDC | UART-мост |

У большинства клонов C3 Super Mini слабая антенна из-за разводки платы:
держите его в прямой видимости роутера. `WiFi.setSleep(false)` в прошивке
уже стоит — без него задержки HTTP на C3 доходят до сотен миллисекунд.
