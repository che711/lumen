# Lumen

Контроллер адресной ленты на ESP32 с декларативным планировщиком и
собственным веб-интерфейсом. Говорит на JSON API, совместимом с WLED, —
за счёт этого Home Assistant находит устройство сам, без custom_component
и без YAML.

Собирается под две платы: **ESP32-C3 Super Mini** и **ESP32 DevKit (WROOM-32)**.

Что внутри: 12 эффектов, 6 палитр, сегменты, пресеты, планировщик с
солнечными якорями, mDNS-обнаружение, OTA, бэкап и восстановление,
мобильный интерфейс без единой внешней зависимости.

---

## Быстрый старт

```bash
pio run -e devkit_wroom32 -t upload        # прошивка
pio run -e devkit_wroom32 -t uploadfs      # интерфейс на LittleFS
pio device monitor
```

Для C3 то же самое с `-e supermini_c3`.

**`uploadfs` обязателен** — без него на устройстве будет только API и
страница-заглушка.

При первом включении поднимается точка доступа `Lumen-XXXX`. Подключаетесь,
открывается портал, вводите сеть и пароль. После перезапуска контроллер
доступен как `http://lumen.local`.

## Тесты

Всё, что проверяется без ESP32 — одной командой (нужны g++, python3, node):

```bash
scripts/test_all.sh
```

Три набора:

- **Ядро планировщика** — 48 тестов, включая прогон целого года.
- **Движок эффектов** — каждый эффект × каждая палитра × весь диапазон
  speed/intensity, с байтами-часовыми для отлова записи мимо буфера.
- **Интерфейс** — прогон скрипта в Node со stub-DOM: ловит опечатки в
  идентификаторах и проверяет разбор времени, цветов и меток якорей.

По отдельности: `pio test -e native`, `scripts/test_effects.sh`,
`node test/ui/uitest.js`.

## Схема подключения

```
   5 V PSU ──┬────────────────────────── +5 V ленты
             │
             ├── 1000 мкФ (по питанию, у первого диода)
             │
             └── GND ──┬──────────────── GND ленты
                       │
                     GND ESP32

   ESP32 GPIO ── 74AHCT125 ── 330 Ом ── DIN ленты
       (3.3 V)     (сдвиг      (гасит
                   до 5 V)     отражения)
```

Пины по умолчанию: **GPIO2** на C3 Super Mini, **GPIO16** на WROOM-32.

Три вещи, на которых ловятся почти все:

- **Level shifter обязателен.** WS2812 ждёт логическую единицу от 0.7×VDD =
  3.5 В, а ESP32 даёт 3.3 В. Часто «работает и так» — до первого нагрева
  или замены катушки.
- **Общая земля** между блоком питания и ESP32. Без неё сигнал плавает.
- **Инжекция питания** каждые ~150 диодов, иначе дальний конец уходит в
  красноту.

## Интерфейс

Один файл `data/www/index.html`, 40 КБ (13 КБ после gzip). Ни сборки, ни
node_modules, ни CDN — на устройстве в локальной сети внешние ресурсы всё
равно недоступны.

Четыре вкладки: **Свет**, **Расписание**, **Пресеты**, **Настройки**.
Вкладки внизу экрана — там, где до них дотягивается большой палец.

Две вещи, ради которых стоило писать свой UI, а не брать чужой:

**Интерфейс подсвечивается цветом ленты.** Акцент во всём макете —
переменная `--glow`, которая берётся из текущего цвета сегмента. Крутите
цвет — вместе с лентой меняются слайдеры, активные чипы и индикатор.

**Лента суток на вкладке расписания.** Семь горизонтальных полос, по одной
на день недели, каждая — сутки от 00:00 до 24:00. Подложка построена не
из абстрактного градиента, а из реальных восхода и заката для ваших
координат: ночь, рассветные сумерки, день, закатные сумерки. Поверх
рисуются окна правил. Сразу видно, почему правило «за 30 минут до заката»
летом начинается в девять вечера, а зимой — в три часа дня, и как окна
накладываются друг на друга.

Состояние приходит по WebSocket. Слайдеры схлопывают события в один запрос
раз в 60 мс — иначе очередь AsyncWebServer переполняется за пару секунд
активного крутения.

## Home Assistant

Настраивать не нужно ничего. Устройство анонсирует mDNS-сервис
`_wled._tcp.local.` — именно его слушает встроенная интеграция WLED.
Через минуту после включения HA покажет его в *Настройки → Устройства и
службы* как обнаруженное.

Что важно знать про эту интеграцию:

- Она требует прошивку 0.14.0 или новее, поэтому `/json/info` отдаёт
  `"ver": "0.15.0"`. Собственный номер Lumen лежит рядом, в поле `"lumen"`.
- Имена сегментов игнорируются: в HA они всегда «Segment 1», «Segment 2».
- Мастер-контроля над всеми сегментами разом у интеграции нет.

Расписание исполняется **на устройстве**. Если сервер с Home Assistant
выключится, лента продолжит жить по графику.

## Планировщик

Правило описывает **интервал**, а не момент времени. Резолвер отвечает на
вопрос «какое правило действует прямо сейчас», а не «какое событие только
что произошло».

Практическая разница: контроллер перезагрузился в 19:00, внутри окна
18:00–23:00. Событийная модель уже пропустила своё «включить в 18:00» и
оставит ленту тёмной. Резолвер посчитает состояние заново и восстановит
нужную яркость — вместе с позицией внутри fade-огибающей.

```jsonc
{
  "id": 1,
  "enabled": true,
  "priority": 0,
  "from": { "type": "sunset", "value": -30 },   // за 30 мин до заката
  "to":   { "type": "clock",  "value": 1410 },  // 23:30 в минутах
  "days": 127,                                  // битовая маска, бит 0 = вс
  "except": ["2026-12-25"],                     // календарные исключения
  "action": { "preset": 3, "bri": 180, "powerOff": false },
  "fadeIn": 1800,
  "fadeOut": 900
}
```

Что умеет ядро:

- якоря на часах, восходе и закате со смещением в обе стороны;
- окна через полночь (22:00 → 06:00) — дни недели проверяются по дню
  **начала** окна;
- приоритеты: правило «вечеринка» перебивает фоновое, не отменяя его;
- ужимание фейдов, если они не помещаются в окно;
- отказ срабатывать, пока время не синхронизировано с NTP.

Восход и закат считаются на устройстве по алгоритму NOAA из координат —
сети для этого не нужно. Для Варшавы расхождение с реальностью в пределах
минуты (21 июня: 04:14 / 21:01, 21 декабря: 07:43 / 15:25).

Перенос на летнее время берёт на себя POSIX TZ-строка
(`CET-1CEST,M3.5.0,M10.5.0/3` для Польши) — таблицы правил в прошивке нет.

Пресет из правила применяется **один раз, в момент смены правила**. Иначе
он затирал бы ручные правки раз в секунду и покрутить цвет было бы
невозможно.

Залить пример:

```bash
curl -X POST http://lumen.local/api/schedule \
     -H 'Content-Type: application/json' \
     -d @examples/schedule.example.json
```

## Эффекты

| # | Название | Что делает |
|---|---|---|
| 0 | Solid | ровная заливка цветом или палитрой |
| 1 | Blink | мигание, скважность от насыщенности |
| 2 | Breathe | плавное «дыхание» по синусу в квадрате |
| 3 | Wipe | заливка бегущим фронтом и стирание обратно |
| 4 | Rainbow | радуга вдоль ленты, плотность от насыщенности |
| 5 | Twinkle | случайные вспышки с плавным появлением |
| 6 | Chase | бегущий блок по фону |
| 7 | Comet | голова с экспоненциальным хвостом |
| 8 | Fire | шум с интерполяцией поколений, низ горячее верха |
| 9 | Scanner | «глаз Ларсона», треугольная волна с разворотом |
| 10 | Theater | каждый третий диод, шаг по кругу |
| 11 | Colorloop | вся лента одним цветом, оттенок по кругу |

Порядок в списке — это индекс `fx` в API. Только добавлять в конец: иначе
сломаются сохранённые пресеты и автоматизации Home Assistant.

Все эффекты — чистые функции от времени, без состояния между кадрами.
«Случайность» в Twinkle и Fire — детерминированный хеш от
`(индекс, поколение)`. Отсюда: рендер можно вызвать для произвольного `t`,
эффекты тестируются без железа, а перезагрузка не рвёт анимацию посередине.

Палитры: Default (цвет сегмента), Rainbow, Party, Ocean, Forest, Lava.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/json` | состояние, info, эффекты, палитры |
| GET | `/json/state` | только состояние |
| GET | `/json/info` | версия, железо, uptime, free heap |
| POST | `/json/state` | управление (совместимо с WLED) |
| GET | `/presets.json` | все пресеты целиком |
| GET | `/api/presets` | список: номер и название |
| DELETE | `/api/presets?id=N` | удалить пресет |
| GET | `/api/schedule` | текущее расписание |
| POST | `/api/schedule` | заменить расписание целиком |
| GET | `/api/status` | время, TZ, солнце, активное правило |
| GET | `/api/config` | настройки устройства (без пароля Wi-Fi) |
| POST | `/api/config` | изменить настройки |
| GET | `/api/backup` | выгрузить расписание и пресеты одним файлом |
| POST | `/api/backup` | восстановить из бэкапа |
| POST | `/api/reboot` | перезапуск |
| WS | `/ws` | состояние в реальном времени |

```bash
# включить радугу на полной скорости
curl -X POST http://lumen.local/json/state \
     -H 'Content-Type: application/json' \
     -d '{"on":true,"bri":200,"seg":[{"id":0,"fx":4,"sx":255,"pal":1}]}'

# сохранить текущий свет как пресет 3
curl -X POST http://lumen.local/json/state \
     -H 'Content-Type: application/json' \
     -d '{"psave":3,"n":"Вечер"}'

# применить пресет 3
curl -X POST http://lumen.local/json/state \
     -H 'Content-Type: application/json' -d '{"ps":3}'
```

## Структура

```
lib/schedule/           ядро планировщика — без Arduino, тестируется на хосте
  solar.{h,cpp}           восход/закат по NOAA, календарь
  schedule.{h,cpp}        резолвер интервалов и огибающих
test/test_schedule/     48 тестов ядра, включая прогон целого года
test/ui/uitest.js       прогон интерфейса в Node со stub-DOM
src/
  core/state.*            состояние под мьютексом
  core/presets.*          сцены в presets.json, чтение по требованию
  core/scheduler_runner.* мост: NTP, TZ, координаты → ядро → лента
  led/effects.*           12 эффектов и 6 палитр
  led/led_controller.*    NeoPixelBus, сегменты, гамма-коррекция
  net/wifi_provision.*    подключение и captive-портал
  net/discovery.*         mDNS `_wled._tcp`
  net/web_server.*        HTTP + WebSocket + весь API
  net/ota.*               обновление по воздуху
  store/store.*           config.json и schedule.json на LittleFS
test/effects/           smoke-тест движка эффектов
data/www/index.html     интерфейс, заливается через uploadfs
examples/               пример расписания
scripts/test_all.sh     все тесты без железа
.claude/skills/         правила проекта для Claude Code
```

Ядро планировщика намеренно не знает ни про Arduino, ни про `time()`: на
вход подаются дата, минута суток и солнечные времена. Поэтому год
виртуального времени прогоняется тестом за долю секунды, а краевые случаи
(переход на летнее время, окна через полночь, полярная ночь) ловятся на
хосте, а не на столе с осциллографом.

## Различия между платами

| | C3 Super Mini | DevKit WROOM-32 |
|---|---|---|
| Ядра | 1 (RISC-V) | 2 |
| Рендер | в основном цикле | отдельная задача на ядре 0 |
| Диодов по умолчанию | 300 | 1200 |
| Сегментов | 4 | 16 |
| Serial | USB-CDC | UART-мост |

У большинства клонов C3 Super Mini слабая антенна из-за разводки платы:
держите его в прямой видимости роутера. `WiFi.setSleep(false)` в прошивке
уже стоит — без него задержки HTTP на C3 доходят до сотен миллисекунд.

- Сегменты в интерфейсе: движок их поддерживает, UI пока правит первый.

  только градиент палитры.
